# Contributing

Thanks for helping improve the Defender MpEngineDb osquery extension. Bug
reports, new Defender tables, and reports from engine builds or hosts we
haven't seen are all welcome.

## Ground rules

- **Never attach or commit a real `mpenginedb.db`, its WAL, or a decrypted
  copy.** They contain file paths, hashes, command lines and user names from
  the host. Share diagnostics instead (see below).
- Decrypted data must never be written to disk by the extension. The only
  exception is the explicit `--decrypt --out` CLI.
- Never write to, or hold write/exclusive handles on, Defender's files.
- Pure Go only (`CGO_ENABLED=0`); no cgo dependencies.

## Development

Requires Go (version in `defender/go.mod`).

```bash
cd defender
go vet ./...
go test -race ./...
cd .. && ./build.sh          # all 6 platforms -> bin/ + bin/SHA256SUMS
```

`docs/DESIGN.md` is the reference for the format, the table columns, the CLI
and the internal API. Keep it in sync with code changes.

### Test fixtures

`defender/internal/mpengine/testdata/oracle/` holds synthetic encrypted
databases generated by an independent, stdlib-only Python script
(`make_fixtures.py`) and verified by a second independent decryptor
(`self_check.py`). They are the ground truth:

- Do not edit expected values to make a test pass.
- Regenerate them only when the fixture design changes:
  `cd defender/internal/mpengine/testdata/oracle && python3 -I make_fixtures.py`

### Adding or changing a table

1. Add a `Spec` in `defender/internal/tables/tables.go` using the declarative
   `Col` types in `spec.go`. Tables must tolerate missing columns and missing
   source tables (empty values / zero rows, never an error).
2. Add tests: against the oracle fixtures where the data exists there, and
   with a small synthetic DB (`sqliteDir` in the tests) using the schema
   **exactly** as Defender creates it.
3. Update the table list in `docs/DESIGN.md` and `readme.md`, and the pack in
   `pack/defender_mpengine.conf` if it is useful for scheduled hunting.

## Reporting a new engine build, key or schema

If `defender_mpengine_status` shows `key_source` other than `known:…`, a
non-`ok` `quick_check`, or an `error`, please open an issue with the output of
`scripts/windows-smoke.ps1` (run as SYSTEM or admin on the affected host). It
records versions, status, row counts and the table schema — never row contents
or the decrypted database. Review the files before attaching them.

## Pull requests

- One logical change per PR, with tests. CI must pass (vet, race tests on
  Linux and Windows, all-platform build, and the live Windows smoke test).
- Run `gofmt` and keep the existing style: small functions, comments that
  explain *why*.
- Describe how you verified the change (fixtures, smoke test, real host).

## Security issues

Please report vulnerabilities privately via GitHub's
[private vulnerability reporting](https://github.com/rakeshrm/osquery-defender-extension/security/advisories/new)
rather than a public issue.
